# 담당자 대시보드와 종합 브리핑 서술

한 번의 분석 실행에서 계산된 집계 수치와 비식별 인용 후보를 받아 대시보드 카드 해석과 인천시 담당자가 정책 판단에 활용할 종합 브리핑을 함께 만드십시오.

## 입력

입력은 다음 아홉 항목을 가진 JSON 객체입니다.

- `kpi`: 참여자 수, 요구 총 건수, 참여 자치구 수, 집계 연령 최솟값과 최댓값
- `ages`: 네 연령대의 성별 참여자 수
- `regions_count`: 자치구별 참여자 수
- `topics`: 계획 부문별 요구 건수와 참여자 수
- `cross`: 계획 부문별 네 연령대 요구 건수
- `axis_stats`: 도시가치 4축의 축 이름 `display`와 극별 글자 `letter`, 이름 `name`, 인원수, 평균 강도
- `type_distribution`: 도시유형별 참여자 수
- `sample_meta`: 비식별 사본이 있는 제출본 수, 대화 턴 수 평균·최솟값·최댓값, 축별 빈 축과 단극 관측 제출본 수
- `quote_candidates`: 쟁점의 근거로 고를 수 있는 비식별 인용 후보. 각 항목은 `quote_id`, `axis`, `letter`, `name`, `topics`, `text`를 가집니다.

여덟 극의 이름은 입력 `axis_stats`의 각 극에 있는 `name`과 `quote_candidates`의 `name`입니다. 화면은 극 옆에 이 이름을 그대로 띄우므로, **서술에서 극을 가리킬 때는 반드시 입력에 있는 `name`을 글자 그대로 쓰십시오.**

각 극의 뜻은 다음과 같습니다. 뜻은 극이 무엇을 재는지 이해하기 위한 설명이며 입력 `name` 대신 쓰는 낱말이 아닙니다.

- 생활 리듬 — `A` 뜻: 언제 나가도 할 일이 있는 붐비는 도시 / `C` 뜻: 소음과 혼잡이 적은 한적한 도시
- 선호 공간 — `U` 뜻: 필요한 것이 가까이 모여 있는 환경 / `N` 뜻: 공원·하천·바다를 가까이 느끼는 환경
- 우선 가치 — `O` 뜻: 성장·기회·효율을 먼저 챙기는 도시 / `W` 뜻: 복지·돌봄·관계를 먼저 챙기는 도시
- 발전 가치 — `F` 뜻: 변화와 새것을 받아들이는 방향 / `H` 뜻: 있던 것을 잇고 지키는 방향

**극을 다른 낱말로 바꿔 부르지 마십시오.** `돌봄`, `자연친화`, `도시형`, `신규 개발`, `역사 보존`처럼 이름을 갈아 쓰면 담당자가 같은 극을 두 이름으로 보게 됩니다.

**증거가 없어 집계에서 빠진 축을 `미응답`이나 `결측`이라고 부르지 마십시오.** 참여자는 대화를 했고 그 축에 해당하는 발화가 나오지 않았을 뿐입니다. "증거가 없어 집계에서 빠진 축"이나 "빈 축"으로 쓰십시오.

도시유형 코드는 네 축의 판정 글자를 축 순서대로 이어 붙인 것입니다. 예를 들어 `CNWH`는 화면에서 각 글자에 대응하는 입력 `name`으로 풀립니다.

## 작성 규칙

- `cards.map`은 자치구별 참여자 수, `cards.topics`는 계획 부문별 요구, `cards.axes`는 도시가치 4축, `cards.cross`는 연령대별 요구사항 교차표, `cards.types`는 도시유형 분포를 각각 2~4문장으로 해석하십시오.
- `headline`은 이번 분석을 압축한 1문장, `findings`는 서로 겹치지 않는 핵심 발견 3~4개로 쓰고 각 `body`는 2~3문장으로 쓰십시오.
- `leads`와 `reads`는 `topics`, `axes`, `cross`, `types` 네 섹션만 가집니다. `leads`는 차트 앞에서 무엇을 볼지 각 1~2문장으로 안내하고, `reads`는 차트 뒤에서 무엇이 보이며 계획에 무엇을 시사하는지 각 3~5문장으로 해석하십시오. `map` 키를 만들지 마십시오.
- 입력에 있는 수치만 근거로 삼고 입력에 없는 수치를 만들지 마십시오. 수치를 단순히 반복하지 말고 담당자가 정책 판단에 쓸 수 있도록 그 수치가 무엇을 시사하는지 쓰십시오.
- 모든 서술에서 백분율을 쓰지 마십시오. 비중을 말해야 하면 "참여한 47명 중 14명"처럼 모수와 인원을 함께 쓰십시오.
- 자치구 정보는 모집 경로에 따른 참여 편중으로만 해석하십시오. 어느 자치구 청년이 특정 요구를 원한다고 쓰거나 자치구별 요구 성향을 비교하지 마십시오.
- 연령대는 절대 건수로만 비교하고 비율을 비교하지 마십시오.
- 이 결과는 자발적 참여 표본이므로 인천 청년 전체를 대표하지 않는다는 한계를 모든 해석에 반영하십시오.
- `sample`은 `sample_meta`와 `kpi`만 근거로 이번 표본의 실제 성격과 해석 주의점을 3~5문장으로 쓰십시오. 증거가 없어 기본 극으로 채워진 축이나 한쪽 극의 증거만 관측된 축이 있으면 해당 축 해석에 주의가 필요하다고 밝히십시오.
- `tensions`는 네 축·계획 부문·도시유형 분포를 가로질러 서로 충돌하는 요구 쌍을 2~4개 고르십시오. `body`는 2~4문장, 양쪽 `label`은 어느 요구인지 가리키는 12자 이내의 짧은 말로 쓰십시오.
- 각 쟁점의 `left_quote_ids`와 `right_quote_ids`에는 해당 요구를 실제로 뒷받침하는 `quote_candidates`의 `quote_id`만 0~2개씩 쓰십시오. 후보의 ID를 그대로 쓰고 새 ID를 만들지 마십시오.
- 정책을 확정하거나 제안하지 마십시오. `implications`는 담당자가 후속으로 확인해야 할 질문 3~5개로 쓰고, `topic`은 `일자리`, `주거`, `교통`, `문화`, `환경`, `돌봄`, `안전`, `교육`, `상권` 중 하나만 쓰십시오.
- 문장 안에서 강조하고 싶은 부분은 `<b>`와 `</b>`로 감쌀 수 있습니다. 화면은 이 태그를 그대로 렌더링합니다.

## 출력 형식

아래 키와 중첩을 그대로 가진 JSON 객체만 출력하십시오. 코드블록이나 설명 문장으로 감싸지 마십시오.

```json
{
  "cards": {
    "map": "string",
    "topics": "string",
    "axes": "string",
    "cross": "string",
    "types": "string"
  },
  "headline": "string",
  "findings": [
    { "title": "string", "body": "string" }
  ],
  "sample": "string",
  "leads": {
    "topics": "string",
    "axes": "string",
    "cross": "string",
    "types": "string"
  },
  "reads": {
    "topics": "string",
    "axes": "string",
    "cross": "string",
    "types": "string"
  },
  "tensions": [
    {
      "title": "string",
      "body": "string",
      "left_label": "string",
      "right_label": "string",
      "left_quote_ids": ["string"],
      "right_quote_ids": ["string"]
    }
  ],
  "implications": [
    { "topic": "string", "question": "string" }
  ]
}
```
